### Последовательность жизненного цикла

1. `apply` получает билет ApplyQueue и отменяет прежнего владельца монитора. Ожидания завершения потока здесь нет.
2. `apply` получает `op`, проверяет покрытие билета и читает актуальное желаемое состояние VPN/WG.
3. `restart` получает тот же reentrant lock и держит его до завершения stop и start. Ошибка stop предотвращает start.
4. После успешного применения запускаются streams и новый владелец монитора. Успешное применение покрывает прежний набор билетов.
5. Прежний worker проверяет отмену после получения try-lock и после health-пробы. Новый monitor.start отменяет прежнего владельца под единым mutex.
6. Отдельный лёгкий watcher проверяет только завершение процесса раз в 3 секунды. Он обновляет трей и событие состояния независимо от длительных сетевых проб. Очистку после падения выполняет основной operation loop.
7. Поколение core увеличивается при stop. Завершение старого warm-up сверяется с поколением под `op`, поэтому оно не записывает результат проверки нового подключения.

Для пользовательских изменений хранилищ выбран откат через публикацию после сохранения. Неуспешная запись оставляет прежний snapshot памяти. Сохранение настроек само по себе по-прежнему не гарантирует их применение к работающему ядру. Соответствующие сообщения UI говорят о необходимости подключения или перезапуска.

## C. QOL

Реализовано следующее.

- Поиск при числе профилей больше восьми, сортировка по последнему ping и сохранение измерений между переходами страниц.
- Последний результат ping остаётся видимым во время новой проверки. Есть время измерения.
- Копирование исходной ссылки при наличии `Profile.link`. Двойной щелчок выбирает профиль, существующий одиночный выбор сохранён. Параллельные запросы выбора блокируются.
- Фактически работающий профиль, время начала текущего запуска и uptime в sidebar.
- Общий закрываемый banner ошибок и закрываемые локальные сообщения. Escape закрывает routing/WG модальные формы и панель вставки WG.
- Подтверждение удаления профиля, подписки, сервиса, туннеля, диагностической цели, элемента списка и очистки журнала.
- Кнопка «Скопировать отчёт» в диагностике. Копируются русские фиксированные названия проверок, исходы, задержки и время. Пользовательские цели, detail, verdict, IP, ссылки и ключи в экспорт не включаются.
- Флаг запроса диагностики из трея переживает монтирование страницы.

Предложения для следующего изменения.

- Сохранять ping вместе с временем между перезапусками приложения, с отдельной политикой срока годности.
- Добавить предупреждение о несохранённых правках при закрытии редакторов через Escape.
- Унифицировать оформление оставшихся локальных информационных сообщений с общим banner, сохранив различие между успешным результатом, частичным импортом и ошибкой.

## D. Что внимательно проверить при ревью

- `serialized_restart`, cancellation monitor и отдельный watcher. Потоки отменяются без join, выполняющаяся ограниченная по времени проба может завершиться после отмены. Доступ к lifecycle сериализован через `op`. Детерминированные тесты проверяют lock и решения, запуск настоящего ядра в тестах отсутствует.
- Монитор теперь проверяет доступность активного proxy и при выключенном auto-switch. Сетевой результат обновляется с прежним периодом 15 с плюс длительность проб. TTL health составляет 45 с, подтверждения перехвата — 15 с. Это выбранные исполнителем ограничения свежести. UI показывает возраст проверки.
- `restore_pending` намеренно разрешает повтор восстановления после частичного изменения ОС, когда прежний proxy уже может перестать определяться как собственный. На реальной ОС следует отдельно проверить частичные отказы и вмешательство другой программы между попытками.
- Windows atomic replace проверен локальными файловыми тестами. Linux ветки gsettings/kwriteconfig и Unix permissions просмотрены по исходникам, Linux сборка и живые системные вызовы в этой сессии не выполнялись.
- Подтверждение TUN проверяет наличие настроенного адреса 172.18.0.1 у активного адаптера. На Linux дополнительно проверяется IFF_UP. Проверка существования адаптера и health proxy имеют разный смысл, оба нужны для зелёного общего индикатора. Полная проверка маршрутов каждого приложения требует отдельной разрешённой интеграционной сессии.
- Настройки в UI могут быть сохранены для следующего подключения. Статус запущенного ядра использует применённые VPN/WG-параметры и имя профиля. Диагностика остаётся явно датированным снимком.
- В ttcm-core остаётся прежний ignored BUG-тест `malformed_saved_outbound_does_not_panic` из `pingall.rs`. Этот дефект генератора pingall не входит в A1–A6. Выдача outbound из ProfileStore теперь безопасно отклоняет не-объекты.
- Полный WebView, приложение и sing-box не запускались. Интеграционное подтверждение поведения трея, TUN и восстановления ОС остаётся задачей ревью в специально разрешённой среде.
