## Найденные ошибки, оставленные для отдельного исправления

### Воспроизводящие игнорируемые тесты

Оба теста отдельно запускались адресно с `--ignored`, оба завершились ожидаемой ошибкой. Существующие live-тесты при этом не запускались.

- `src-tauri/ttcm-core/src/config.rs:735`, `proxy_port_must_not_collide_with_controller`. Порт 9090 разрешён настройками и одновременно занят Clash controller. Порт 9089 конфликтует через geo inbound, а на Linux нужно учитывать также PAC и верхнюю границу port+2. Требуется единая проверка набора зарезервированных портов в UI, команде сохранения и при чтении старых настроек. Проверка генератора сама по себе не исправит все входные пути.

- `src-tauri/ttcm-core/src/pingall.rs:80`, `malformed_saved_outbound_does_not_panic`. Сохранённый `outbound=42` десериализуется как `Value`, затем запись `outbound["tag"]` паникует. Такая же предпосылка есть в методах выдачи outbound в ProfileStore. Требуется валидация сохранённых профилей с сообщением об ошибке и согласованная обработка во всех генераторах. JSON `null` сам превращается в объект, поэтому тест использует число.

### Ошибки, обнаруженные чтением кода

Для перечисленных сценариев интеграционное воспроизведение не выполнялось.

- `src-tauri/src/core/mod.rs:708`. Весь restart не удерживает `op`, отдельно блокируются stop и start. Между ними может выполниться другой запрос. Нужна сериализация всей операции с согласованием действий monitor и apply.

- `src-tauri/src/monitor/mod.rs:34`, `:42`, `src-tauri/src/core/mod.rs:97`. Concurrent apply может запускать/останавливать monitor при удерживаемом `op`. Monitor сам вызывает stop/restart и может ждать `op`, в то время как его join ждёт завершения потока. Кроме того, флаг и handle хранятся под разными mutex, и конкурентные start/stop могут рассогласовать их. Требуется единый владелец жизненного цикла и детерминированные конкурентные тесты.

- `src-tauri/src/sysproxy/mod.rs:104`, `:123`. Backup удаляется даже после ошибки восстановления. После следующего запуска прежние настройки уже неоткуда восстановить. Следует сохранять backup и возможность повторной попытки до успешного restore. Это затрагивает аварийное восстановление и требует тестируемой подмены OS-слоя.

- `src-tauri/src/sysproxy/os.rs:345`, `:390`. Linux-ветки игнорируют статусы команд записи и могут возвращать успех при неудаче gsettings/kwriteconfig. Требуется передавать ошибки и учитывать частичное применение нескольких значений.

- `src-tauri/src/settings/mod.rs:188`, `src-tauri/src/profiles/mod.rs:104`, `:139`. Ошибки записи настроек и профилей подавляются. UI может показать сохранение или импорт, которые исчезнут после перезапуска. Нужны Result на границах хранилищ, атомарная запись и согласование памяти с диском.

- `src-tauri/src/profiles/mod.rs:104`. Повторный ручной импорт тех же ссылок добавляет дубликаты с новыми ID. Политика идентичности должна учитывать имя, параметры и происхождение из подписки. Без неё исправление может удалить намеренно созданные варианты. `apply_subscription` повторно использует ID по ссылке/имени и заменяет только свою подписку, но транзакционные сценарии обновления не покрыты новыми тестами.

- `src-tauri/src/diag/mod.rs:140`. Разделение цели по первому двоеточию ломает IPv6, а указанный пользователем порт теряется в URL проверки через VPN. Также TCP-проба сервера сама по себе не подтверждает доступность UDP-протокола HY2. Требуется общий парсер диагностической цели и учёт протокола.

- `src-tauri/src/pingall.rs:64`. Конфиг записывается до `resolve_singbox(app)?`. Если бинарник не найден, временный файл остаётся. Требуется разрешать бинарник до записи либо создавать cleanup guard сразу после неё.

- `src-tauri/src/clash/mod.rs:97`. Закрытие WebSocket до следующего LOG_FLUSH теряет последний накопленный batch. Требуется финальная отправка при выходе и тест завершения потока.

- `src-tauri/src/geo/mod.rs:124`. Замена нескольких файлов последовательными rename может завершиться частично. Заявленное сохранение всего старого набора при ошибке диска не обеспечено. Нужна транзакционная смена поколения либо откат и очистка временных файлов.

- `src-tauri/src/platform/win/mod.rs:14`. Успешный spawn PowerShell считается успешным elevated relaunch. Отмена UAC после этого не передаётся приложению, которое уже может выйти. Требуется дождаться результата операции и передать ошибку через Tauri-команду.

- `src/App.tsx:114`. При переходе на диагностику событие dispatch отправляется до монтирования страницы и установки её listener. Запуск из трея может открыть страницу без запуска проверки. Требуется сохранить запрос в React/store либо обработать его после монтирования.

- `src/pages/RoutingPage.tsx:88`, `src/pages/SettingsPage.tsx`, `src/pages/WireGuardPage.tsx`. Несколько быстрых сохранений полных snapshot могут перезаписать изменения друг друга, часть обработчиков не перехватывает отклонённые Promise. Нужна сериализация сохранений или backend patch API с единым отображением ошибки. Массовая замена обработчиков выходит за рамки небольшого локального исправления.

## Неоднозначные места и ограничения проверки

- Сервисы идут раньше пользовательских правил в `routing.rs:341`. Для одинакового адреса выигрывает сервис. Для независимых сервисов с одинаковыми адресами сохраняется порядок выбора. Намерение продукта здесь не задано, приоритет оставлен прежним.

- `process_name` не входит в поддерживаемые пользовательские kind. Неизвестный kind превращается в `domain_suffix`. Процессные правила существуют только для обхода внешнего интерфейса в генераторе конфигурации.

- `subscription.rs` не поддерживает импорт Clash/sing-box JSON, TUIC также не поддерживается парсером ссылок. Проверки не добавляют эти форматы. `parse_userinfo` всё ещё использует f64, поэтому огромные целые теряют точность, а нечисловые специальные значения требуют отдельной политики проверки. `is_stub` считает заглушкой любой порт 1, хотя это допустимый номер порта.

- `wireguard.rs` поддерживает комментарии `#`, повторные list-поля, CRLF, IPv6, ключи с padding, keepalive, DNS search domains и round-trip. Существующие тесты проходят. Комментарии `;` не поддерживаются. Не менял синтаксис без решения о совместимости с wg-quick. Catch-all `/0` и обе половины `/1` исключаются из автоматических routed_subnets, что закреплено новым тестом.

- `pac::parse_rule_set` собирает только простые верхнеуровневые matchers. Логические/инвертированные правила и IPv6 не моделируются полностью. В Linux `core::pac_script` получает исходный RouteSpec, тогда как generator дополнительно меняет маршруты для WG и provider-list. Полное соответствие PAC работающей конфигурации требует отдельной проверки.

- `core::warm_up` не имеет идентификатора поколения запуска. Проверка старого подключения может завершиться уже после restart и обновить статус нового. Проверки WG также используют текущие settings, которые могли ещё не примениться к запущенному ядру.

- `SysProxyLine` при отключённом управлении прокси показывает предупреждение и в штатном режиме TUN. В этом режиме отсутствие applied_port ожидаемо.

- В UI остаются места с асинхронным обновлением состояния после ухода со страницы и таймерами без cleanup. Основные повторяющиеся интервалы статуса WireGuard и подписки на backend-события имеют cleanup. Проверка UI выполнялась чтением кода, TypeScript и локальными моками. Настоящий WebView не запускался.

- Матрица проверяет структуру JSON, ссылки и порядок правил. Она не заменяет проверку бинарником sing-box 1.14. Системный прокси управляется app-crate и отдельного флага в GenOptions не имеет. Матрица не выполняет OS-действия. Linux-ветки анализировались по исходникам, сборка выполнялась в Windows.
